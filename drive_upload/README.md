# Supplementary material — "One Timeline, Many Renderings" (ICSC 2026)

These are the full example artifacts referenced from the paper. Upload this
**whole folder** to **Zenodo**, mint a DOI, and replace the placeholder
`https://doi.org/10.5281/zenodo.XXXXXXX` in `paper.tex` (the `\supplementaryurl`
command) with the real DOI URL before submission.

Everything here is generated by the Temporal System paclet itself.

## Main example — the Fig. 2 stress fixture

The most complex fixture of the paclet's Csound test suite (sixteen `sine_osc`
notes, eight `click` hits, four triggers, six composing curves, section markers,
and a 4/4 → 5/8 → 7/8 → 3/4 meter grid at 96 BPM).

| File | Referenced in paper | Content |
|---|---|---|
| `timeline_example.csd` | §4 (aggregated `.csd`) | Full Csound rendering: k-rate curve signals, generated bound copies of both instruments, marker comments, trigger events |
| `timeline_example.wav` | §4 (its `.wav`) | Audio compiled by the paclet |
| `timeline_example_click.csd` | §5 (click track) | Click track of the same timeline across the meter changes |
| `timeline_example_click.wav` | §5 (click track) | Audio of that click track |
| `paper_curve_osc.json` | §4 (OSC JSON) | OSC projection of a linear amplitude curve (0→1, sampled at 10 Hz); the excerpt quoted inline is from this file |
| `timeline_example.nb` | §2 / Fig. 2 (generating notebook) | Notebook that builds the fixture, exports the Fig. 2 timeline, and produces every file here |
| `paper_note.csd` | §4 | One-note rendering whose `i`-statement is quoted in the paper |
| `paper_click.csd` | §5 | Minimal 4/4 click whose score is described in the paper |
| `instruments/` | §4–§5 (`.orc` instruments) | The `sine_osc.orc` and `click.orc` instruments the `.csd` files `#include` |

## Four-backend synchrony demonstration — §6 "Keeping the Projections Synchronous"

`sync_demo/` is the reproducible demonstration behind §6. One authored timeline
— two 4/4 bars then 3/4, 120 then 90 BPM — is projected to all four backends
(`_A` files), then re-rendered after a **single tempo edit** (the second segment
90 → 60 BPM, `_B` files). The three time-domain backends (Csound `p2`, OSC
`time_ms`, click) place the same events at the same seconds and move together
under the edit; the MusicXML export is byte-identical (`demo_sync_A.musicxml` and
`demo_sync_B.musicxml` are the same file — notation lives in beat space).

| File | Content |
|---|---|
| `demo_sync_A.csd` / `demo_sync_B.csd` | Csound score, original / edited tempo |
| `demo_sync_click_A.csd` / `demo_sync_click_B.csd` | Click track, original / edited tempo |
| `demo_sync_osc_A.json` / `demo_sync_osc_B.json` | OSC event list (`time_ms`), original / edited tempo |
| `demo_sync_A.musicxml` / `demo_sync_B.musicxml` | MusicXML 4.0 (partwise) — identical across the tempo edit |
| `propagation.pdf` / `propagation.png` | The synchrony figure (Csound / OSC / click aligned on the seconds axis) |
| `make_sync_demo.wls` | Generator that reproduces every file above from the paclet |

To regenerate, point the script at a Temporal System checkout and run it; the
artifacts are rewritten next to the script:

```
TEMPORAL_SYSTEM_ROOT=/path/to/temporal-system wolframscript -file make_sync_demo.wls
```

To compile a `.csd` on a machine without the paclet checkout, repoint its
`#include` lines at the bundled `instruments/` copies (or pass Csound
`--include-dir instruments`), then run e.g. `csound timeline_example.csd`.
